# Админ-панель Fold Papper

Гайд о том, как дать пользователю права администратора, где это настраивается и что умеет админка.

## Коротко

1. Зарегистрируйтесь на сайте обычным способом.
2. Запустите бэкенд с переменной `ADMIN_USERNAMES=ваш_username`.
3. Войдите на сайт заново: в меню под аватаром появится пункт **Админ-панель** (адрес `/admin`).

Роль сохраняется в базе, поэтому переменная нужна только один раз. Остальных администраторов можно назначать уже из самой админки.

---

## Где это настраивается

| Что | Где |
|---|---|
| Переменная окружения | `ADMIN_USERNAMES` — username через запятую: `anna.chili,igor_habanero` |
| Свойство Spring | `app.admin-usernames` в `backend/src/main/resources/application.yml` (по умолчанию берётся из `ADMIN_USERNAMES`) |
| Код, который выдаёт роль | `backend/src/main/java/com/foldpapper/admin/AdminBootstrap.java` — срабатывает при каждом старте |
| Где хранится роль | колонка `users.role` (`USER` / `ADMIN`), миграция `V2__admin_and_reports.sql` |
| Кто может открыть `/api/v1/admin/**` | правило `hasRole("ADMIN")` в `backend/src/main/java/com/foldpapper/config/SecurityConfig.java` |

При старте `AdminBootstrap` проходит по списку и выдаёт каждому найденному пользователю роль `ADMIN` (заодно снимает с него блокировку, если она была). В логе бэкенда появится строка:

```
Пользователь anna.chili назначен администратором (ADMIN_USERNAMES)
```

Если пользователь не найден, в логе будет предупреждение `ADMIN_USERNAMES: пользователь … не найден`. Значит, нужно сначала зарегистрироваться, а потом перезапустить бэкенд.

## Способы назначить первого администратора

### Linux / macOS / Git Bash

```sh
cd backend
ADMIN_USERNAMES=anna.chili mvn spring-boot:run
```

### Windows

PowerShell:

```powershell
cd backend
$env:ADMIN_USERNAMES="anna.chili"; mvn spring-boot:run
```

Командная строка (cmd):

```bat
cd backend
set ADMIN_USERNAMES=anna.chili
mvn spring-boot:run
```

### IntelliJ IDEA

**Run → Edit Configurations… → FoldPapperApplication → Environment variables**: `ADMIN_USERNAMES=anna.chili`.

### Собранный jar

```sh
ADMIN_USERNAMES=anna.chili java -jar target/foldpapper-backend-0.1.0-SNAPSHOT.jar
# или аргументом:
java -jar target/foldpapper-backend-0.1.0-SNAPSHOT.jar --app.admin-usernames=anna.chili
```

### Напрямую через базу (запасной вариант)

Если перезапускать бэкенд неудобно, выполните из корня проекта:

```sh
docker compose exec postgres psql -U foldpapper -d foldpapper \
  -c "UPDATE users SET role = 'ADMIN' WHERE username = 'anna.chili'"
```

Роль начнёт действовать сразу, без перезапуска. Список администраторов:

```sh
docker compose exec postgres psql -U foldpapper -d foldpapper \
  -c "SELECT username, role FROM users WHERE role = 'ADMIN'"
```

## Как назначать и снимать администраторов дальше

**Админ-панель → Пользователи**, затем кнопки у нужного пользователя:

- **Сделать админом** — выдать роль (с подтверждением).
- **Снять админа** — вернуть роль `USER`.

Изменения действуют **сразу**. Перезаходить на сайт не нужно: роль и блокировка проверяются в базе при каждом запросе.

> Если пользователь указан в `ADMIN_USERNAMES`, после снятия роли он снова станет админом при следующем перезапуске бэкенда. Чтобы снять роль насовсем, уберите его из переменной.

## Что умеет админ-панель

| Раздел | Возможности |
|---|---|
| **Обзор** | Число пользователей, пинов, перцев и досок, открытые жалобы, заблокированные. Графики новых пинов, регистраций и перцев за 14 дней (дни — в вашем часовом поясе), кнопка «Показать таблицей». |
| **Жалобы** | Очередь открытых жалоб на пины и профили, от старых к новым. На пин: **Удалить пин** — пин удаляется, все жалобы на него закрываются. На профиль (с пометкой «Профиль»): **Заблокировать** — пользователь блокируется, все открытые жалобы на его профиль закрываются. **Отклонить** — всё остаётся как есть. Вкладки «Меры приняты» и «Отклонённые» — история решений. |
| **Пользователи** | Поиск по имени, username и email, фильтры «Админы» и «Заблокированные». Выдача и снятие роли, блокировка с причиной, разблокировка. Флажок «N жалоб» — открытые жалобы на профиль. |
| **Пины** | Поиск по всем пинам, флажок с числом открытых жалоб, удаление любого пина. |

Жалобы оставляют обычные пользователи кнопкой с флажком:

- **на пин** — на странице чужого пина. Причины: спам, 18+, оскорбления, авторские права, другое. Одна жалоба на пин от человека.
- **на профиль** — рядом с кнопкой «Подписаться» в чужом профиле. Причины: спам или бот, выдаёт себя за другого, оскорбления, неприемлемый профиль, другое. Одна *открытая* жалоба на профиль от человека: после разбора можно пожаловаться снова.

## Блокировка со страницы профиля

Администратор видит в чужом профиле кнопку **Заблокировать** (вместо флажка жалобы) — то же окно, что и в разделе «Пользователи»: причина вводится вручную или выбирается одним нажатием. Заблокированный профиль у администратора помечен красным бейджем с датой и причиной, там же кнопка **Разблокировать**. Обычные посетители статус блокировки не видят. У другого администратора кнопки нет: сначала снимите с него роль в разделе «Пользователи».

## Правила и ограничения

- Себя нельзя разжаловать или заблокировать, чтобы не остаться без единого администратора.
- Администратора нельзя заблокировать: сначала снимите с него роль.
- Повторить уже сделанное нельзя: заблокировать заблокированного, разблокировать активного или выдать ту же роль. API отвечает `409` («Пользователь уже заблокирован» и т. п.), а на сайте кнопка сразу меняется на обратную («Заблокировать» ↔ «Разблокировать»). Если действие уже выполнил другой админ или вы сами в другой вкладке, придёт та же ошибка, и страница подтянет актуальное состояние.
- Заблокированный пользователь сразу теряет доступ. Сайт его разлогинивает, а при попытке войти он видит «Аккаунт заблокирован: <причина>». Его пины остаются на сайте, при необходимости удалите их в разделе «Пины».
- Удаление пина необратимо.
- Скрыть страницы `/admin` на фронтенде — лишь удобство. Настоящая защита на бэкенде: без роли `ADMIN` API админки отвечает `403`.

## API админки

Все запросы требуют `Authorization: Bearer <token>` пользователя с ролью `ADMIN`.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/v1/admin/stats?tz=Europe/Moscow` | Сводка и активность за 14 дней |
| `GET` | `/api/v1/admin/users?q=&filter=admins\|banned&page=` | Пользователи |
| `PATCH` | `/api/v1/admin/users/{id}` | `{"role": "ADMIN"\|"USER", "banned": true\|false, "banReason": "…"}` |
| `GET` | `/api/v1/admin/pins?q=&page=` | Пины с числом открытых жалоб |
| `DELETE` | `/api/v1/admin/pins/{id}` | Удалить любой пин |
| `GET` | `/api/v1/admin/reports?status=OPEN\|RESOLVED\|DISMISSED` | Жалобы |
| `POST` | `/api/v1/admin/reports/{id}/resolve` | `{"action": "DELETE_PIN"\|"DISMISS"}`; `DELETE_PIN` — только для жалоб на пин |

Жалоба на профиль закрывается блокировкой: `PATCH /api/v1/admin/users/{id}` с `{"banned": true}` переводит все открытые жалобы на этого пользователя в `RESOLVED`. Профиль `GET /api/v1/users/{username}` для администратора дополнительно содержит `bannedAt` и `banReason`.

Для пользователей:

- `POST /api/v1/pins/{id}/reports` с `{"reason": "SPAM"|"NSFW"|"OFFENSIVE"|"COPYRIGHT"|"OTHER", "comment": "…"}`;
- `POST /api/v1/users/{username}/reports` с `{"reason": "SPAM"|"NSFW"|"OFFENSIVE"|"IMPERSONATION"|"OTHER", "comment": "…"}`.

Все эндпоинты с примерами есть в Swagger: <http://localhost:8080/swagger-ui.html>, раздел **Admin**.

## Если что-то не работает

- **Нет пункта «Админ-панель» в меню.** У пользователя нет роли. Проверьте лог бэкенда (строку `назначен администратором`) или список админов SQL-запросом выше, затем обновите страницу.
- **В логе `пользователь … не найден`.** Username написан с ошибкой или пользователь ещё не зарегистрирован. Регистр букв не важен.
- **`/admin` показывает «Такой страницы нет».** Вы вошли под пользователем без роли, либо роль сняли. Выйдите и войдите заново.
- **Внезапно разлогинило с сообщением «Ваш аккаунт заблокирован модератором».** Аккаунт заблокирован. Разблокировать его может другой администратор, или можно выполнить SQL: `UPDATE users SET banned_at = NULL, ban_reason = NULL WHERE username = '…'`.
